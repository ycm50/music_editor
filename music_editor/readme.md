# RCP 简谱编辑器 (C++ 核心)

基于简谱的音乐编辑和播放工具。核心是纯 C++20 库（无 Qt 依赖），桌面端与安卓端共用同一份源码完成**解析 → 物理合成 → WAV 编码**。

---

## 项目结构

```
music_editor/
├── CMakeLists.txt        # 根构建文件
├── core/                 # 共享库（纯 C++20，无需 Qt）
│   ├── note_parser.h/.cpp  # RCP 解析: 音符/元数据/物理参数/乐理校验
│   ├── tone_gen.h/.cpp     # 物理合成 + 乐器库 + 混响 + 体检指标
│   ├── ai_prompt.h/.cpp    # AI 系统提示词 + 可自检的示例乐谱（两端共用）
│   └── wav_writer.h/.cpp   # WAV 写入 (16-bit PCM, 单/立体声)
├── ../tools/             # 自检工具（check_prompt / test_syntax）
├── player/               # 音乐播放器（需 Qt6::Multimedia）
├── save/                 # RCP→WAV + --analyze 体检（纯 C++，无 Qt）
├── ui/                   # GUI 编辑器（需 Qt6::Widgets）
├── 1.rcp / twinkle.rcp   # 乐谱数据文件
├── run_player.bat        # 播放器启动脚本（Windows）
└── run_ui.bat            # GUI 启动脚本（Windows）
```

## 依赖

- **编译器**: C++20 (GCC/MinGW 13+ / MSVC 2022+)
- **构建工具**: CMake ≥ 3.16, Ninja 或 MinGW Makefiles
- **Qt**: Qt 6.x (推荐) 或 Qt 5.15+
  - `player`: 需要 `Qt6::Multimedia` 模块
  - `ui`: 需要 `Qt6::Widgets` 模块
  - `save` 和 `core`: **不依赖 Qt**

## 构建

```bash
cd music_editor
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=A:/msys64/ucrt64
cmake --build build
```

> MSYS2 (UCRT64) 依赖: `mingw-w64-ucrt-x86_64-qt6-base mingw-w64-ucrt-x86_64-qt6-multimedia mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja`

### Windows 特殊说明

`player` 和 `ui` 依赖 Qt DLL。编译后运行：

```bash
# 方法一：使用启动脚本（自动设置路径）
run_player.bat 1.rcp
run_ui.bat

# 方法二：手动设置 PATH
set PATH=A:\msys64\ucrt64\bin;%CD%\build\player;%PATH%
build\player\player.exe 1.rcp
```

> `ui` 为 GUI 子系统（`WIN32_EXECUTABLE`），启动不弹终端窗口；它会自动在同目录或 `../` 下查找 `player.exe` / `save.exe`（发布包为同目录平铺）。

> **闪退排查**：`player` / `ui` 是动态链接 Qt 的，缺少 Qt DLL 时会立刻闪退。`run_ui.bat` / `run_player.bat` 已内置 Qt6 `bin` 目录自动探测（先看 `PATH` 里的 `qmake6.exe`，再依次试 `A:\msys64\ucrt64\bin`、`A:\msys2\ucrt64\bin`、`A:\msys64\mingw64\bin`、`C:\msys64\...`、`A:\Qt\6.*\mingw_64\bin`），并会打印 `[run_ui] Qt6 found at: ...`。若 Qt 装在别处，编辑脚本设 `set "QTBIN=你的Qt\bin"` 即可。手动验证：
> ```bat
> set PATH=A:\msys64\ucrt64\bin;%CD%\build\ui;%PATH%
> build\ui\ui.exe
> ```

> ⚠ **构建路径不要含中文**：Qt 的 `moc` 在非 ASCII 路径下无法创建输出文件。若源码目录含中文，先建 ASCII 目录联接再构建：
> `mklink /J A:\tmp\me-boot "A:\你的路径\music_editor"`

# RCP 文件格式

## 整体结构

```
# ── 注释以 "# " 开头 (井号后必须跟空格, 以免与升号 #4 冲突) ──
@ref A4=440          # 参考音高
@bpm 96              # 速度
@beat 0.625          # 标准拍长 (一个四分音符的秒数) = 60/BPM
@meter 4/4           # 拍号 (仅用于小节对齐校验)
@timbre harp         # 乐器
@voice 1             # 声部 1
6.04!f 7.04 1.+04 2.+04      # 每行 = 1 小节
@voice 2             # 声部 2 (独立时间轴, 与声部 1 纵向叠加)
6.-02 [6.-02+1.02]_[6.-02+1.02]
```

行序无关，`@` 元数据行可任意顺序出现。**兼容旧格式**：第 1 行若写 `BPM,基准频率,标准拍长`（如 `120,261.63,0.5`）照旧可用；第 2 行若为"逗号分隔非负数字"（至少两个）且不是合法音符行，视为谐波振幅表；第 3 行若可被持续比例解析器接受，视为持续比例行（会记一条 deprecated 提示）。

### 解析容错与严格模式

- **`parse_rcp`（默认，用于播放/导出）：容错**。单个 token 写错时记入 `warnings`（含行号与原因）并跳过它，其余音符照常渲染 —— 一个笔误不该让几百行的谱整体打不开。
- **`parse_rcp_strict`（用于"检查乐谱"/自动化校验）：严格**。任何 token 语法错误直接抛 `std::invalid_argument`，消息形如 `第 3 行 token "5.00:5": 拍长分母必须 >= 1 (...)`。

UI 的校验按钮走严格模式，方便定位错误；实际播放走容错模式，并在状态栏显示跳过了哪些 token。

## 头部参数

| 写法 | 含义 |
|---|---|
| `BPM,基准频率,标准拍长` | 旧写法（三值逗号分隔，会检查 BPM 与拍长是否自洽） |
| `@bpm 96` / `@tempo 96` | 速度（仅信息，实际时值以拍长为准） |
| `@ref 261.63` | 1=do 的频率 |
| `@ref C4` / `@ref A4=440` / `@ref 1=C` | 等价的音名写法 |
| `@beat 0.625` | 标准拍长（四分音符秒数） |
| `@meter 4/4` / `3/4` / `6/8` | 拍号，用于 `--analyze` 的小节对齐校验 |
| `@timbre 名称` / `@instrument 名称` | 乐器（见下方乐器表） |
| `@acoustic 名称 k=v;...` | 自定义物理模型 |
| `@dyn mf=0.6,p=0.3` | 保留（自定义力度映射，当前仅做语法校验） |
| `@voice N` | 声部标记，每个声部独立时间轴 |

## 音符语法

```
<音级>[变音].<八度><拍长分母>[附点][t|q][!力度][@音色][$物理覆盖][~|']
```

| 部分 | 取值 | 说明 |
|---|---|---|
| **音级** | `1`~`7` | do re mi fa sol la si |
| | `0` 或 `r` | 休止符（渲染为**真静音**，不占合成开销） |
| **变音** | `#` `b` `##` `bb` `n` | 可写在音级前或后：`#4` 与 `4#` 等价；`n` 为还原 |
| **八度** | `0` | 中音 |
| | `+` / `-`（可连写） | 高/低八度，范围 ±4：`++`=高两个八度，`--`=低两个八度 |
| **拍长分母** | `4` | 四分音符（1 拍） |
| | `2` / `1` / `8` / `16` / `32` | 二分 / 全 / 八分 / 十六分 / 三十二分 |
| **附点** | 分母后加 `.` | 时值 ×1.5：`4.`=附点四分（1.5 拍）、`2.`=附点二分（3 拍） |
| **连音符** | 分母后加 `t` | 三连音（时值 ×2/3）：`4t` 三个音平分一拍 |
| | 分母后加 `q` | 五连音 |
| **力度** | `!pp` `!p` `!mp` `!mf` `!f` `!ff` 或 `!0.42` | 0~1，默认 `1.0` |
| **物理覆盖** | `$dec=0.4/sus=0/atk=0.01/br=0.8/B=0.001` | 逐音覆盖乐器参数，多项用 `/` 分隔 |
| **演奏法** | `~` | 连奏（标记保留） |
| | `'` | 断奏（时值 ×0.5） |

**连音 `_`**：连接相邻的同音高音符，**时长相加且只起音一次**。

```
1.04_1.04              → 一个二分音符 (起音一次, 包络连续)
5.04_5.08_5.08         → 一个二分音符
[1.02+3.02]_[1.02+3.02] → 一个全音符的三度和弦 (两个音都只起音一次)
```

**和弦 `[...]`**：成员用 `+` 或 `,` 分隔（推荐 `,`，因为 `+` 与八度记号冲突），同一时刻纵向发声，成员时值自动统一到最长。和弦后面的**修饰符作用于整个和弦的每个成员**：

```
[1.04+3.04+5.04]         → C 大三和弦, 一拍
[6.04,1.+04,3.+04]       → Am 和弦 (推荐写法)
[1.02,3.02,5.02]!f       → 三个音同时强奏 (力度作用于整组)
[1.02,3.02]_[1.02,3.02]!pp  → 和弦连音成四拍, 整组弱奏
[1.04,3.04]$dec=0.3      → 整组衰减时间常数 0.3s
```

**多声部**：`@voice N` 之后的音符进入该声部，每个声部从时间 0 开始独立推进，最终纵向混合。

**完整示例**

```
3.+2        3 的高八度二分音符
#4.+8       升 4、高八度、八分音符
b7.-2       降 7、低八度、二分音符
0.04 / r.04 休止一拍 (真静音)
2.08.       附点八分音符
1.04t       三连音中的一个音
1.+4!ff     强奏
5.+2$dec=0.3/sus=0   该音衰减 0.3s、无稳态 (拨弦感)
```

## 物理乐器模型

`@acoustic` 用 6 个物理量描述一件乐器，取代了旧的"逐倍频时间窗"写法：

```
f_n   = n · f₁ · √(1 + B·n²)                        分音频率 (劲度 → 非谐性)
A_n(t)= A_n(0) · (sus + (1-sus)·e^(−t/τ_n))          分音包络 (绝对时间)
τ_n   = damp / n^exp                                 频率相关衰减
A_n(0)= br^(n−1)                                     分音初始振幅 (频谱倾斜)
f_n ≥ fs/2 的分音被丢弃                               抗混叠
```

| 键 | 单位 | 含义 | 典型值 |
|---|---|---|---|
| `B` | — | 非谐性系数 | 理想弦 0；吉他 1e-5；钢琴 2e-4；钟 3e-2 |
| `damp` | 秒 | `τ₁`（或用 `/` 给指数，或用 `,` 逐分音列出） | 钢琴 2.45；小提琴 0.55；长笛 0.35 |
| `exp` | — | `τ_n = damp/n^exp` 的指数 | 0.55 ~ 0.9 |
| `atk` | 秒 | 起音时间（平方上升） | 击弦 3ms；弓弦 55ms；气流 80ms |
| `sus` | 0~1 | 稳态电平；`0`=纯衰减型，`>0.6`=持续型 | 钢琴 0；小提琴 0.82；管风琴 1.0 |
| `rel` | 秒 | 谱面结束后的 cos² 自然收尾 | 0.02 ~ 0.10 |
| `br` | 0~1 | `A_n(0)=br^(n−1)` 的亮度 | 长笛 0.30；钢琴 0.68；八音盒 0.86 |
| `noise` | 0~1 | 起音噪声量（弓毛/气流/击弦） | 吉他 0.35；长笛 0.30 |
| `stereo` | 0~1 | 分音左右扩散（保留参数） | 竖琴 0.25 |

**关键点**：`damp` 是**绝对秒数**，与音符写多长无关——钢琴 C4 弹 1 拍和弹 4 拍，同一时刻的振幅完全相同。谱面只决定"何时松键"，音色由物理决定。

### 内置乐器

| 名称 | B | damp(s) | atk(s) | sus | br | 音色特征 |
|---|---|---|---|---|---|---|
| `piano` | 2e-4 | 2.45 | 0.003 | 0.00 | 0.68 | 击弦，起音噪，指数衰减 |
| `violin` | 1e-4 | 0.55 | 0.055 | 0.82 | 0.88 | 弓弦持续，中高频丰富 |
| `flute` | 0 | 0.35 | 0.080 | 0.90 | 0.30 | 纯净气息，高次谐波弱 |
| `guitar` | 1e-5 | 1.10 | 0.002 | 0.00 | 0.78 | 指尖拨弦，快衰减 |
| `harp` | 8e-5 | 2.20 | 0.003 | 0.00 | 0.80 | 晶莹，长衰减 |
| `bells` | 3e-2 | 4.50 | 0.001 | 0.00 | 0.62 | 金属钟，强非谐 |
| `music_box` | 6e-3 | 1.60 | 0.001 | 0.00 | 0.86 | 音梳，清脆 |
| `organ` | 0 | 6.00 | 0.045 | 1.00 | 0.75 | 全稳态长音 |

用 `save --list` 可随时查看。旧式裸谐波音色（`piano`/`violin`/`flute` 的振幅表）仍可用 `-t` 指定，但与同名物理乐器冲突时以物理乐器为准。

### 旧式两行写法（deprecated）

```
120,261.63,0.5
1,0.7,0.5,0.3,0.2,0.1            ← 第 2 行: 谐波振幅
0-1!0-0.8!0-0.6!{0.1-0.3,0.5-0.7>}   ← 第 3 行: 持续比例
1.04 3.04 5.04
```

持续比例的时间窗按**音符时长比例**解释（这与"物理绝对时间"矛盾，故已不推荐）；`0-0` 表示该倍频全程不存在。新文件请改用 `@acoustic`。

## 体检报告（`--analyze`）

```
$ save demos/01_piano_nocturne.rcp --analyze --notes 3
音色模型   : piano
时长       : 119.452 s @ 44100 Hz 立体声
音符/休止  : 108 / 0
和弦块/最大同时发声 : 15 / 3
音域       : 130.813 Hz (C3) ~ 783.991 Hz (G5)
峰值 / RMS : 0.795 / 0.129   峰均比 15.807 dB
直流偏置   : -4.992e-08   (|DC|<1e-4 为合格)
混叠分音   : 0 个被丢弃 (Nyquist=22050 Hz)
小节时长   : 3.636 s   总长 32.000 小节
对齐偏差   : -0.000 s (对齐)
```

| 指标 | 物理含义 | 合格标准 |
|---|---|---|
| 直流偏置 | 波形均值（直流分量） | `|DC| < 1e-4`（非 0 说明合成有 bug） |
| 峰均比 (crest) | 峰值/有效值，动态范围 | 12 ~ 20 dB 较自然 |
| 静音占比 | `|x| < 1e-4` 的样本比例 | 休止符多则高 |
| 混叠丢弃分音 | 越过 Nyquist 被丢弃的分音数 | 高音区多属正常；为 0 最干净 |
| 对齐偏差 | 音符总长对拍号小节的偏差 | `< 0.02 s` 为对齐 |
| 频谱重心 | `Σ A_n f_n / Σ A_n`，客观"亮度" | 用于横向比较音色 |

## 与原 Python 版相比的改进

| # | 问题 | 修复 |
|---|---|---|
| 1 | Python 列表缺逗号致字符串拼接 | C++ 版从 RCP 文件解析，无硬编码列表 |
| 2 | 注释写 120BPM 实际传 388 | 头部 BPM 与拍长不一致时会**报出警告**并以拍长为准 |
| 3 | WAV 导出无音符间隔 / 全曲统一断奏 | 改为**物理包络 + 自然收尾**：衰减型乐器（钢琴/吉他）自然分离，持续型（弓弦/风琴）自然相连，不再插入硬编码 50ms 死间隔 |
| 4 | UI/save 两套音色不一致 | 统一乐器表定义在 `core/tone_gen.h` / `core/note_parser.*` |
| 5 | 未使用的 import | C++ 版无冗余引用 |
| 6 | 线程安全问题 | UI 通过 `QProcess` 启动外部进程播放，不存在竞态 |
| 7 | 播放只响一声 / 格式不被后端接受 | 渲染 float32，播放格式优先 `Float`、回退 `Int16`（兼容 FFmpeg/WASAPI 后端），分块写入避免缓冲溢出 |
| 8 | 休止符被合成成 0.25mHz 正弦（产生 0.47 直流爆音） | 休止符改为**真静音**（零样本） |
| 9 | 逐音峰值归一，力度与音色绝对值被抹平 | 改为**整曲一次性归一**（保留相对力度），音符级力度进入包络 |
| 10 | 包络按音符时长比例，长短音音色不一致 | 包络改为**绝对时间**（秒），音色与音符长短解耦 |
| 11 | `:` 连音语义损坏（`5.00:5` 被读成 4 秒） | `:` 明确拒绝并提示；新增 `_` 真正连音（时值相加 + 单次起音） |
| 12 | 谐波越 Nyquist 折返成非谐波杂音 | 增加**抗混叠**：越界分音丢弃并计入报告 |
| 13 | 音符行被误判为音色行（整段旋律静默丢失） | 先判定是否为合法音符行，且音色行判据排除含 `. _ ! $ @` 的行 |
| 14 | 无法写和弦/多声部/变音记号/附点/三连音 | 全部支持：`[a+b]`、`@voice`、`#4`/`b7`、`4.`、`4t` |

## AI 生成提示词

提示词正文的**唯一来源**是 `core/ai_prompt.cpp`（`score_system_prompt()`），桌面端 `ui` 与安卓端经 JNI 的 `getScorePrompt()` 都取这一份，不再两端各写一份而漂移。

它教给模型的记法要点：

- **头部**固定为 `BPM,基准频率,标准拍长` 三值一行，并强调"标准拍长必须精确等于 60/BPM"
- **乐器**从 8 种内置乐器里按情绪选（`@timbre`），必要时用 `@acoustic` 自定义物理参数
- **拍号** `@meter`，并要求"每行 = 1 小节、行内拍数之和必须等于拍号"
- **音值表**明确给出分母→拍数换算（含 6/8 时每行 3 拍）
- 变音 `#4`、附点 `4.`、三连音 `4t`、连音 `_`、和弦 `[1.04,3.04,5.04]`、力度 `!mf`（并说明修饰符可作用于整个和弦）
